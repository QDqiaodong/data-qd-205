# 离线扫描带归档契约（micro_objects.archive）

本文档定义 `micro_objects.archive` 的字段、错误、格式与资源边界。该入口在
现有 `process` 之外新增，不改变任何既有公开入口的入参、返回语义与错误；
样例与测试只使用通用合成像素。

## 1. 入口与数据流

```python
from micro_objects import build_archive, ArchiveReader

build_archive(target, header, strips, budget)
reader = ArchiveReader(target)
```

- `build_archive` 接收板头、按从上到下一次性迭代的行带流和补存格预算，把一个
  自包含的 SQLite 数据包原子发布到未使用的本地路径 `target`。
- 行带迭代器只被消费一次；不补行、不覆盖、不回退、不要求调用方重播。
- 普通异常或坏输入都不会留下可打开的目标；已存在的目标永远不会被替换。
- `ArchiveReader` 以只读 URI 打开单个文件，复制到断网机器后仍可读取，不依赖
  原始行带、网络或任何服务。

## 2. 板头字段

| 字段 | 约束 |
| --- | --- |
| `width` | 整数 1..256 |
| `height` | 整数 1..32768 |
| `pixel_size` | 两个十进制字符串，沿用 `process` 的 `number()` 口径，均为正数 |
| `connectivity` | 整数 `4` 或 `8` |
| `selection.min_pixels` | 整数 1..板像素数（`width*height`） |
| `selection.exclude_border` | 布尔 |

新入口不沿用旧的逐对象包围盒扫描预算，也不会因拓扑工作拒绝合法长板；
`min_pixels` 的上限按本入口允许的最大板像素数校验。

## 3. 行带字段与连续性

每条行带：

| 字段 | 约束 |
| --- | --- |
| `band_id` | 1..64 位 ASCII 字母、数字、下划线或连字符，板内唯一 |
| `start_row` | 非负整数，板内起始行 |
| `offline` | 布尔，是否申请该带原件下线 |
| `mask` | 1..64 行等宽 `0/1` 字符串，宽度等于板宽 |
| `intensity` | 与 `mask` 同尺寸的整数矩阵，取值 0..65535 |

调用方必须从第 0 行连续覆盖到第 `height-1` 行。以下情况整体拒绝且不发布：
多余行、越界、空洞、覆盖、重复 `band_id`、类型错误（布尔不被当作整数）、
行高超过 64、强度越界，以及读取中断。背景格也带真实强度，零是合法强度而非
空值。

## 4. 对象身份与交付指标

整板连通分量在流式过程中跨带计算；带边不是板边。对象身份是其首个前景坐标
`[x, y]`（先行后列、零基），行带 ID、分带方式与临时并查标签都不属于对象身份；
同一块板改用不同分带，对象键与内容保持不变。未获选对象不进入对象索引。

每个获选对象提供与 `process`/`measure.py` 同口径的精确指标：

- 像素数 `pixel_count`
- 半开包围盒 `bbox = [x0, y0, x1, y1]`
- 物理面积 `area = count * sx * sy`（精确有理数字符串）
- 四边暴露周长 `edge_perimeter`
- 像素中心质心 `centroid`（精确有理数字符串）
- 强度和 `intensity_sum` 与均值 `mean_intensity`
- 互补连通孔洞数 `holes`；计算某对象孔洞时，其他对象的格子属于该对象的补集
- 整板触边状态 `touches_border`

`iter_object_samples(key, batch_size=...)` 按光栅序分批流式返回该对象的全部
前景坐标与原强度，不读出其他对象，也不生成整板标签面；批次可迭代，单行带读取
只占用一个条带大小的空间。

## 5. 下线申请、成本与预算

- 每个申请下线的行带，只有其每一格都能从包恢复时才批准；否则整带跳过，余额
  不变。
- 行带成本 = 该行带内未作为获选前景交付的格子数（全部背景格 + 所有未获选前景
  格）。获选对象的前景格随对象交付，不占补存预算。
- 申请按板上顺序处理；成本不超过当时余额就批准并扣除，否则记
  `insufficient_budget`。余额为零时，零成本带仍可批准。
- 未申请带不补存、不影响余额，决策固定为 `not_requested`。
- 决策常量：`approved`、`not_requested`、`insufficient_budget`。
- `list_band_decisions()` 返回每条带的决策，申请带带实际成本；
  `used_budget()` 返回最终已用预算。

同一坐标的强度样本只保存一份：对象交付与已批准行带恢复引用相同的像素行。
未批准带中，除获选前景外的原始像素一律不保留；这些格子不会用零填补。

## 6. 行带恢复

`recover_band(band_id)` 仅对 `approved` 的带返回其二进制掩膜、原始强度矩阵与
起始行；恢复按条带索引定位，不扫描对象库。未批准、未申请或未知的 ID 都抛出
`ArchiveError`，无法恢复的格子绝不以零凑数。

## 7. SQLite 包格式

包格式标识为 `micro-objects-archive/1`，是一个标准库 `sqlite3` 数据库，含：

- `meta`：格式标识、板头、选择条件、预算、已用预算、计数等。
- `strips`：条带序号、ID、起始行、高度、申请标志、决策与成本。
- `components`：对象键、包围盒、精确度量、孔洞、触边标志与选择标志。
- `pixels`：每个板格一行，含坐标、掩膜、强度、所属条带、所属临时标签与对象；
  条带与对象索引支撑按带恢复和按对象分批读取。

构建期使用本地临时数据库与标签链；发布时删除构建临时表并 `VACUUM`，再以
`os.replace` 原子移动到目标。

## 8. 资源边界

- 构建期保留的 Python 数据：并查集、统计量、回收槽位与两行槽位数组均为 O(W)，
  槽位总数不超过约 2W+1；当前条带像素行为 O(W·B)；条带元数据为 O(S)，其中 W
  为板宽、B 为最大实际行带高度、S 为行带数。整体稳态内存满足
  O(W·B + W + S)，不保留整板、全体对象表或全部像素索引。
- 孔洞的有界泛洪在组件最终化时执行，临时 `bytearray` 随该组件包围盒面积线性
  增长并在返回前释放；本地中间数据（像素行、标签链、组件表）随板像素数与行带
  数线性增长，不按各对象包围盒面积分别展开。SQLite 页缓存与该临时缓冲是随板
  像素数增长的临时空间，不属于常驻 Python 工作集。
- 读取端单对象样本按 `batch_size` 分批；单条带恢复使用该条带大小的空间。

## 9. 错误汇总

所有构建与读取错误统一为 `micro_objects.ArchiveError`（`ValueError` 子类）：
板头字段越界、行带结构或类型错误、覆盖/空洞/重复 ID、读取中断、预算越界、目标
已存在、包格式无法识别、未知对象或条带 ID、未批准带恢复、批次大小非法等。
未知对象键在 `get_object` 上抛 `KeyError`。
